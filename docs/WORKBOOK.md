## 8. UI/UX Design Standards 2026

### 8.1 Grid & Layout System

**Grid:** 12-column on desktop (divisible by 2,3,4,6) → 8-column tablet → 4-column mobile.

**Container widths (max-content + centered):**

| Breakpoint | Max content width | Side padding | Gutter |
|------------|------------------|-------------|--------|
| Mobile (<640px) | 100% fluid | 16px | 16px |
| Tablet (640-1024px) | 720-960px | 24px | 24px |
| Desktop (1024-1440px) | 1140-1280px | 24-32px | 24-32px |
| Ultra-wide (>1440px) | 1280px max, centered | 48-80px | 32px |

**Rules:**
- Content never touches screen edge
- On ultra-wide: extra space = background/imagery only, do not stretch text full width
- Blog/article content max: 640-760px (65ch max line length)

### 8.2 Spacing System (8-Point Grid)

All padding, margin, gap values must be multiples of 8. No random values.

| Token | px | rem | Use case |
|-------|-----|-----|----------|
| space-1 | 8px | 0.5rem | Gap icon+label, badge padding |
| space-2 | 16px | 1rem | Card internal padding, button padding X |
| space-3 | 24px | 1.5rem | Card padding, grid gap, section py mobile |
| space-4 | 32px | 2rem | Section padding mobile, gap between cards |
| space-5 | 48px | 3rem | Section spacing tablet |
| space-6 | 64px | 4rem | Major section break desktop |
| space-7 | 96px | 6rem | Hero padding, large section spacing |
| space-8 | 128px | 8rem | Max vertical spacing (rare) |

**Section vertical spacing (py):**

| Device | Section spacing |
|--------|----------------|
| Mobile | 32-40px (py-8 to py-10) |
| Tablet | 48-64px (py-12 to py-16) |
| Desktop | 80-96px (py-20 to py-24) |

**Card padding:** 24px (p-6)
**Grid gap:** 24-32px (gap-6 to gap-8)
**Button padding:** 12-16px vertical × 20-24px horizontal (py-3 px-5 to px-6)
**Touch targets (mobile):** minimum 44-48px height for all clickable elements

### 8.3 Typography Scale 2026

#### Rules:
- Use rem units only (never px for font-size)
- Use CSS `clamp()` for fluid scaling — no media queries for font sizes
- 2 font families max: 1 heading (Plus Jakarta Sans / Manrope), 1 body (Inter)
- Do NOT override root font-size (no 62.5% trick — breaks user accessibility)
- Body text never below 16px
- Line length: 60-75 characters per line (65ch max-width)

#### Fluid Type Scale (CSS clamp values)

| Level | clamp() formula | Desktop size | Weight | Line-height | Letter-spacing |
|-------|----------------|-------------|--------|-------------|----------------|
| Display | `clamp(2.75rem, 2rem+3vw, 6rem)` | 48-96px | 800 (ExtraBold) | 1.05 | -0.03em |
| H1 | `clamp(2rem, 1.2rem+3vw, 3.5rem)` | 44-56px | 800 (ExtraBold) | 1.05-1.1 | -0.03em |
| H2 | `clamp(1.5rem, 1rem+2vw, 2.5rem)` | 32-44px | 700 (Bold) | 1.1-1.2 | -0.02em |
| H3 | `clamp(1.25rem, 1rem+1vw, 1.75rem)` | 24-28px | 600 (SemiBold) | 1.2-1.3 | normal |
| H4 | `clamp(1.125rem, 0.9rem+0.5vw, 1.375rem)` | 20-22px | 600 (SemiBold) | 1.3-1.4 | normal |
| H5 | `clamp(1rem, 0.9rem+0.25vw, 1.125rem)` | 18px | 500 (Medium) | 1.4 | normal |
| H6 | `clamp(0.875rem, 0.8rem+0.25vw, 1rem)` | 16px | 500 (Medium) | 1.4 | normal |
| Body | `clamp(1rem, 0.9rem+0.5vw, 1.125rem)` | 16-18px | 400 (Regular) | 1.5-1.7 | normal |
| Small | `clamp(0.8rem, 0.75rem+0.25vw, 0.875rem)` | 13-14px | 400 | 1.5 | +0.02em |

#### H1-H6 visual hierarchy check:
```
H1: 44px — clearly largest, page title only
H2: 34px — visually distinct from H1, clearly section header
H3: 26px — subsection, clearly smaller than H2
H4: 21px — card titles, body large
H5: 18px — minor headings
H6: 16px — same as body weight
Body: 17px — comfortable reading
```

**Flat hierarchy warning:** Never use H1=32px, H2=28px, H3=24px — indistinguishable. Difference between each level must be visually obvious.

## 9. Technical Architecture

### Current
- Static HTML site
- No build tools
- Single index.html (placeholder portfolio template in local)
- Live site appears to be custom static

### Recommended
- **Framework:** None needed. Pure HTML/CSS/JS is fine for this scale.
- **But:** Use a local build step for asset optimization:
  - PostCSS/Tailwind CLI (purge unused styles, minify)
  - Image optimization pipeline (sharp or squoosh CLI)
  - HTML minification

OR use Astro (recommended by travel SEO experts for static + fast + pre-rendered HTML). But simple HTML is acceptable for launch speed.

### Essential Technical Upgrades
1. Generate sitemap.xml
2. Create robots.txt
3. Add JSON-LD schema partial to every page
4. Preload critical assets (hero font, hero image)
5. Defer non-critical CSS/JS
6. Lazy load below-fold images
7. Set explicit width/height on all images
8. Use `<picture>` tag with WebP + AVIF + JPEG fallback
9. Enable gzip/brotli compression on server
10. Set caching headers (Cache-Control: max-age=31536000 for static assets)

## 13. Tone of Voice & Brand Language

> Color palette, typography, spacing, and layout specs are in **Section 8 — UI/UX Design Standards 2026**. This section covers language only.

### Tone of Voice
- Professional but warm ("Khushi" = happiness in Hindi)
- Confident: "100% owned fleet", "Bangalore's most trusted"
- Specific: use numbers, prices, guarantees
- Conversational in FAQs, never robotic
- No jargon — speak like a helpful travel agent you trust

### Writing Rules
- Lead with benefit, then feature ("Enjoy Maharaja comfort with 1x1 pushback seats")
- Use active voice ("We own every vehicle" not "Every vehicle is owned by us")
- Short sentences. One idea per sentence.
- Address user directly: "You choose the vehicle, we handle the rest"
- CTA verbs: Book, Get, Check, Enquire, Start
- Avoid: superlatives without proof ("best", "greatest" — use "Bangalore's most trusted" backed by 4.9★)

### Voice Examples
| Do | Don't |
|----|-------|
| "Book in 2 minutes on WhatsApp" | "We offer an efficient booking process" |
| "₹28/km, all-inclusive" | "Competitive pricing structure" |
| "100% owned — no last-minute switches" | "We pride ourselves on fleet ownership" |
| "We reply in 5 minutes, 24/7" | "Our support team is responsive" |

## 15. Risks & Edge Cases

### Risk: WhatsApp only booking
- **Problem:** No email capture = no retargeting possible
- **Fix:** Add optional web form (name + phone + destination) that captures lead data before WhatsApp redirect

### Risk: Static HTML limits scaling
- **Problem:** Adding blog posts requires manual HTML edits
- **Fix:** Consider static site generator (Astro, 11ty) if content volume grows past 20 pages

### Risk: Competitor copies strategy
- **Problem:** Schema, answer blocks, pricing pages are easily copied
- **Fix:** Double down on moats: 100% owned fleet (un-copyable), review volume, brand trust

### Risk: PageSpeed drops after schema addition
- **Problem:** JSON-LD inline is fine, but CSS/JS from CDN can slow load
- **Fix:** Move to purged build, defer all non-critical resources

### Risk: AI citations fluctuate
- **Problem:** AI models change, citations drop suddenly
- **Fix:** Monitor monthly, maintain freshness, diversify citation sources
